# Private two-site WireGuard firmware candidate

RE-SS-01 is the server (192.168.12.1, 10.99.0.1); RE-CS-02 is the initiating client (192.168.11.1, 10.99.0.2). Only the server needs a reachable public UDP51820 endpoint. DDNS cannot make an inbound CGNAT mapping reachable; the server learns the client's translated source port from authenticated traffic.

`RE-Mesh-BUILD.yml` builds both roles with `WAN_PROTOCOL=pppoe` by default. It uses separate `OPENWRT_SS01_WAN_PPPOE_USERNAME/PASSWORD` and `OPENWRT_CS02_WAN_PPPOE_USERNAME/PASSWORD` repository secrets. The global old pair is not reused across sites. Explicit DHCP builds remain possible. A blank install needs per-device PPPoE, WG identity/peer, a verified client endpoint, Headscale enrollment and permitted subnet routes to operate unattended. A retained-config upgrade may preserve old UCI over the image defaults and requires the separate device acceptance procedure.

`WG_SITE_SS01_PRIV` / `WG_SITE_CS02_PRIV` contain local identities. By the documented role convention, `WG_SITE_SS01_PEER` is the CS02 public key and `WG_SITE_CS02_PEER` is the SS01 public key. Injection rejects empty or malformed keys and self-peering.

Mesh DDNS publishing is disabled. The workflow does not pass Aliyun credentials or bake a provider configuration. The generated basic section is disabled, and both early first-boot migration and WG bootstrap stop/disable ddns-go and disable every restored UCI instance. Existing device provider data is preserved. The installed service retains directory0700/file0600 hardening for any later explicit administrator use.

A new client has no baked DNS/static endpoint. Configure a verified endpoint through the existing management path before expecting direct WG connectivity; until then Tailscale is the fallback. A live learned endpoint takes priority over an existing managed UCI endpoint during bootstrap; either is preserved ahead of any optional initial hostname. The daemon never refreshes DNS, substitutes a historical static IP, writes an endpoint or reloads the interface; it only probes the WG path and manages its own LAN route. WAN address changes require an administrator to verify/update the endpoint while DDNS is disabled.

The early migration removes the two known legacy rc.local daemon launch commands, including foreground and background shell wrappers, before rc.local executes. Other commands, control flow, permissions and user data are preserved. procd is the only firmware daemon owner; the infinite loop is never called by rc.local. This migration is scoped to images with the private WG site seed.

The private seed has permissions0600 and is safely shell-quoted. The persistent `/data/wg/wg-server.key` or `wg-client.key` is reused only when its public identity matches the seed; mismatches hold bootstrap instead of overwriting administrator keys. Bootstrap requires a real block-backed ext4/f2fs `/data`. netifd receives the actual private key, not a filename. Bootstrap is delayed to the procd startup after storage initialization.

Both roles have WG/LAN forwarding and explicit policy rules before proxy/Tailscale: UDP source51820 to main, WG tunnel and remote LAN to table60. No default route is inserted into table60. Automatic peer LAN routes are disabled; a role-aware daemon installs its owned LAN route only after an interface-bound WG ping succeeds. Two failed probes remove that LAN route, allowing subsequent Tailscale table52 lookup. A live ping wins over an old handshake; failed probes never trigger an interface reload that could overwrite a learned endpoint. A WG-only tunnel probe route remains while LAN traffic uses Tailscale, allowing direct-path recovery without a LAN blackhole or a false successful probe via Tailnet. No background throughput transfer or unverified SSH probe is used. Tailscale route acceptance and bidirectional LAN forwarding remain subject to existing ACLs and control-plane route approvals.

TCP/udp2raw remains disabled; no faketcp nft exception is installed in these candidates. Enabling it requires independent runtime validation. Changing a DDNS A record never changes the server's learned client endpoint. The old historical static WAN fallback is removed. The daemon does not perform DNS endpoint lookup.

Artifacts MUST be age encrypted before upload. A `private` suffix alone is not encryption or an access-control mechanism. Both raw images contain recoverable WG/PPPoE and enrollment material in their immutable filesystem; do not distribute decrypted images, factory images or config backups. Only encrypted envelopes and safe metadata may leave the private build boundary. The existing recipient public key is used; its private identity stays local. Public releases and raw artifact upload paths are excluded for encrypted candidates.

This change authorizes build/test/artifact verification only. No device has been flashed, rebooted, disconnected or had its live routing modified. Fresh boot, PPPoE reconnection, DDNS-disabled persistence, inter-LAN endpoint traffic, WG failure/Tailscale fallback and restoration remain device acceptance gates. Before a later retained upgrade, inventory and retire only the exact old managed `/data/bin/wg-path-daemon.sh`/health startup entries so they cannot race the new procd owner; do not delete user scripts or unrelated cron jobs. Keep an independent rescue path and timed rollback for any disruptive test.
